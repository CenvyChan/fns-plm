## 1. 先给结论

这项工作不应继续沿着“先把所有节点填满，再一次性做成一棵级联树”的路线推进。更稳妥的路线是：

1. **把号码唯一性从分类树中独立出来。** 分类树回答“这是什么物料”；命名空间、身份键和流水池回答“这个物料号能否唯一分配”。
2. **把材质、表面处理、系列、形状做成并行维度。** 每条分支声明哪些维度必填、哪些禁止、哪些只进入规格属性，不能因为字典存在就自动做全组合。
3. **先实现受限声明式规则和发布前静态校验。** 不引入自由脚本；预览不消耗流水，正式分配才占号。
4. **第一条纵向切片选“成品冷插骨架 + 半成品冷插骨架 + 五金分支”。** 它同时覆盖跨族碰撞、并行材质、表面处理、固定 `00`、预览/分配/重试和假 ERP 回读。
5. **ERP 先做只读证据和假 ERP 验收。** 2026-10-14 的独立只读 MCP 探针已确认用户环境变量存在、服务暴露 10 个工具且没有写工具，但 `BD_MATERIAL` 元数据和组织 `001` 的窄查询都返回“会话信息已丢失”；因此 ERP 仍是 `PENDING_EXTERNAL`，不能把本轮演算当作 ERP 字段核验。

## 2. 本文使用的三类事实

为了避免设计稿把推断伪装成生产规则，后续每个结论都标成以下三类之一：

| 类型 | 含义 | 可以做什么 |
|---|---|---|
| 图像/代码事实 | 原图可读、夹具已有节点、当前代码已有行为 | 可以进入测试夹具、静态校验和设计边界 |
| 推荐方案 | 为了让系统可维护而提出的默认模型 | 可以进入草稿规则、原型和假 ERP；不能直接激活生产 |
| 业务/ERP待证实 | 总类是否入码、正式流水、目标账套字段和真实物料样本 | 未确认前只能阻止对应分支发布，不能阻塞无关分支的设计工作 |

当前夹具的 `confirmed` 只表示原图标签可辨，`activeRules=[]`、`confirmedFamilyIds=[]` 仍表示没有可激活的正式生产规则。

## 3. 关键演算一：跨族前缀碰撞不是理论问题

### 3.1 输入

取两个原图结构相同、业务身份不同的代表分支：

| 分支 | 逻辑段草图（不含流水） | 业务身份 |
|---|---|---|
| 成品冷插骨架 / 单槽 / PET | `01｜01｜01｜01` | 成品、冷插骨架、单槽、PET |
| 半成品冷插骨架 / 未插针 / 单槽 / PET | `01｜01｜01｜01` | 半成品、冷插骨架、单槽、PET |

这里的 `01` 只表示当前矩阵中的候选段，不表示已经批准的正式编码长度、分隔符或流水位数。

### 3.2 三种分配结果

假设流水显示为 4 位，仅用于演算：

| 策略 | 成品第一次 | 半成品第一次 | 结论 |
|---|---:|---:|---|
| 两个族各自从 `0001` 起一池 | `010101010001` | `010101010001` | **完整号码相同，禁止** |
| 不加总类，但两个族共享同一前缀流水池 | `010101010001` | `010101010002` | 可避免号码重复，但业务上两个族共用号码序列 |
| 总类前缀候选为成品 `1`、半成品 `2` | `1010101010001` | `2010101010001` | 当前代表样例不碰撞，但前缀位数和旧号兼容仍需确认 |

因此，`family` 或“物料族”不能只存在于 MES 的附加字段里，再让 ERP 看到两个相同的完整物料号。生产发布必须选择以下一种已批准策略：

- **策略 A：总类前缀进入号码。** 推荐作为新规则候选；先拿脱敏旧号样例确认是一位、两位还是其他形式。旧物料号不重编。
- **策略 B：不进入号码，但所有可碰撞分支共用同一原子流水池。** 这是可行的兼容方案，但它不能证明两个族的号码前缀具有业务可读性。

在 A/B 没有确认之前，只阻止会产生同前缀的分支发布，不阻止规则目录、维度字典、预览引擎和假 ERP 的开发。

### 3.3 发布校验要比较最终字符串，而不只是带分隔符的逻辑段

跨版本改变段数或流水位数也可能碰撞。例如，`前缀 01 + 四位流水 0101` 与 `前缀 0101 + 两位流水 01` 都得到最终字符串 `010101`。这个反例并不表示当前项目实际采用这两种流水位数，而是说明**仅比较逻辑段元组、或只查同版本同前缀，不足以证明完整物料号唯一**。发布校验应覆盖已发布版本、历史分配号和目标账套只读可见的既有物料号；运行时还要有最终编码唯一约束。

## 4. 关键演算二：编码唯一性和物料身份不是同一件事

建议把唯一判断拆成两层：

```text
业务物料身份键 = tenant + account + 主分类叶节点 + 必需维度值 ID + 身份规格字段
流水池定位键 = 目标 ERP 账套 + 已确认的编码命名空间/前缀
ERP 完整编码唯一键 = 目标 ERP 账套 + 最终完整编码
```

### 4.1 三个重试场景

| 场景 | 身份键变化 | 正确行为 |
|---|---:|---|
| 同一个物料重复点击“分配” | 不变 | 幂等返回原分配，不再取新流水 |
| 只改备注或非身份规格 | 不变 | 仍视为同一物料；不能因为任意文本变化取新号 |
| 改变身份规格，例如尺寸从 A 改为 B | 变化 | 视为新物料候选，重新走预览和分配 |

因此，不能把整段规格自由文本直接当作去重键，也不能把“尺寸、颜色都不入编码”误解为“尺寸、颜色都不影响物料身份”。是否影响身份，应由每个分支的 `identityFields` 明确列出。

### 4.2 PLM/ERP 版本边界

- 图纸、BOM、工艺路线的修订版本默认挂在物料身份上，不自动改变物料号。
- 如果业务认定变更后物理上不可互换，则应产生新的身份键和新物料号；这需要业务确认，不能由“图纸版本号变化”单独推导。
- 规则版本改变的是“今后如何求值”，不是历史编码的重算触发器。历史分配记录必须保留旧规则版本和字典快照。

## 5. 关键演算三：流水策略必须可解释

### 5.1 推荐的流水命名空间

建议流水池至少使用：

```text
tenant + targetAccount + codeNamespace/prefix
```

创建组织、使用组织首先是授权和 ERP 作用域，不应未经 ERP 证据就被当成流水命名空间的一部分。若目标账套证实 ERP 允许不同组织共享同一物料号，则组织不进入号码池；若 ERP 约束要求组织独立编号，再通过已确认的 `codeNamespace` 表达，而不是散落在页面判断中。

如果两个 MES 租户实际上写向**同一个 ERP 账套**，仅按 `tenant + account` 各起一池仍可能在 ERP 撞号；这种映射必须共享一个由 ERP 账套拥有的号码分配权，或在发布前证明两个租户使用互斥的编码命名空间。跨租户隔离是 MES 授权要求，不能代替 ERP 号码唯一性。

### 5.2 `批量增量25` 不能直接解释为步长 25

两种解释的前几项不同：

| 解释 | 前三次序列 |
|---|---|
| 批量数量为 25，流水仍按 1 递增 | `1, 2, 3` |
| 流水步长为 25 | `1, 26, 51` |

“批量增量25”目前不足以选择其中一种。推荐先把它建模为**业务批量属性候选**，不写入序列算法；业务明确说“每次领用/采购批量”时进规格或采购属性，业务明确说“号码步长”时才进入 `sequencePolicy.step`。

### 5.3 位数容量只是容量计算，不是生产参数批准

在起点 1、步长 1 的演算假设下：

| 流水位数 | 可分配数量（保留 `0000` 不使用） |
|---:|---:|
| 4 位 | 9,999 |
| 5 位 | 99,999 |

如果步长为 25，理论可用槽位约为 4 位 400、5 位 4,000，但这只在步长确实为 25 时成立。系统应在发布前验证耗尽策略，不允许溢出后截断、回绕或静默扩位。

### 5.4 预览、分配、失败和版本切换

推荐行为：

1. **预览不占号。** 同一请求重复预览返回同一逻辑前缀和占位流水，不写正式分配记录。
2. **分配在事务中占号。** 唯一约束冲突时重试同一身份键；不能把数据库异常转换成另一个猜测号码。
3. **分配后 ERP 失败不随意回收。** 号码进入可对账状态；是否可回收必须由单独的号码回收策略批准，否则会产生号码重用风险。
4. **规则版本切换不回零。** 例如版本 1 已分配 `0001`–`0003`，版本 2 的同一命名空间下一次应从 `0004` 继续，而不是从 `0001` 重启。
5. **幂等键必须跨重试有效。** `tenant + account + idempotencyKey` 至少要能找回原分配尝试、当前状态和 ERP 回读结果。

## 6. 并行维度的可维护模型

不再把所有维度压成一棵父子树；每个分支使用受限声明式模型：

| 对象 | 作用 | 例子 |
|---|---|---|
| `classificationPath` | 主身份和基础段位 | 成品 → 注塑件 → 冷插骨架 → 单槽 |
| `dimensionRefs` | 可复用并行字典值 | `injection-material.PET` |
| `requiredDimensions` | 当前分支必须选择的域 | 冷插骨架要求注塑材质 |
| `forbiddenDimensions` | 防止跨域误选 | 注塑分支禁止五金材质 |
| `fixedSegments` | 服务端自动生成的固定段 | 配件或五金毛坯的 `00` |
| `identityFields` | 决定新物料的规格属性 | 厚度、尺寸、颜色或电气参数，按分支声明 |
| `segments` | 最终有序段位 | 路径段、维度段、固定段，不能重复引用同一节点 |
| `sequencePolicy` | 流水池、位数和耗尽策略 | 目标账套 + 编码命名空间 |

求值过程固定为：

```text
选择主分类路径
  → 校验叶节点和分支唯一命中
  → 校验并行维度适用域及确认状态
  → 生成固定 00 等服务端段
  → 按已发布段序组装逻辑前缀
  → 做跨分支前缀碰撞检查
  → 预览或在事务中分配流水
  → 保存身份键、规则版本、字典快照和分配轨迹
```

这里不生成变压器类别 × 系列的笛卡尔积。变压器候选类别、系列和适用关系仍未确认，必须按显式的 `allowedCombinations` 录入后才允许预览。

### 7.2 证据线：不让 ERP 阻塞规则内核

ERP 证据线独立推进：

1. 先确认宿主是否真正重启了 `k3cloud_readonly`；当前宿主工具列表没有暴露 K3Cloud 工具，不能以“配置文件存在”代替重启证据。
2. 在环境变量已加载的独立只读进程中，保留 `10 个工具、0 个写工具` 的安全边界。
3. 会话恢复后只查询 `BD_MATERIAL` 元数据和少量组织 `001` 样本，不做 Save、Push、Submit、Audit。
4. 将返回字段映射到 MES 的 `erp_material_code`、名称、规格、创建组织、使用组织、状态和修改时间；字段未经目标账套响应确认前保持候选。
5. 只读证据完成后，再在假 ERP 中完成 Save/View/UNKNOWN/重试分支；真实 ERP 写入另立验收单。

## 8. 对第 8 节的决策压缩：只保留 6 个需要业务拍板的问题

### D1：总类是否入码

- **推荐：** 新规则候选默认采用“总类进入号码”的模型，因为已演算出成品/半成品同前缀碰撞。
- **必须确认：** 总类是 1 位还是 2 位、是否兼容既有物料号、是否所有族共用同一规则。
- **未确认处理：** 以 `includeTopClassPrefix` 作为草稿开关；碰撞分支禁止发布，不自动写入生产。

### D2：流水的正式参数

- **推荐测试假设：** 4 位、起点 1、步长 1、左侧补零、耗尽即阻断。
- **必须确认：** 正式位数、起点、步长、是否允许断号、失败是否回收。
- **未确认处理：** 可在假规则和测试中使用，但生产状态保持不可激活。

### D3：“批量增量25”的业务含义

- **推荐：** 暂不解释为流水步长；先作为批量/采购属性候选。
- **必须确认：** 它是批量数量、每批占用 25 个流水号，还是序列步长 25。
- **未确认处理：** 不进入 `sequencePolicy.step`。

### D4：固定 `00` 的适用条件

- **推荐：** `00` 作为规则产生的固定段，用户不可编辑；只有矩阵已明确的分支使用。
- **必须确认：** 每个分支是固定 `00`、必选维度还是二者都存在。
- **未确认处理：** 只在已明确的草稿分支启用，不能以“未知材质”替代。

### D5：材质/处理/系列的段序与身份规格

- **推荐：** 段序由分支规则冻结；材质和处理可以并行引用，但是否决定新物料由 `identityFields` 决定。
- **必须确认：** 至少提供一组成品和半成品真实脱敏编码样例，确认段序、总类、流水边界。
- **未确认处理：** 页面可显示“段来源草图”，不输出可写 ERP 的正式完整编码。

### D6：ERP 物料号和组织边界

- **推荐：** 物料主身份、创建组织、使用组织、MES 授权范围分开建模；组织选择不直接改写号码。
- **必须确认：** 目标账套中相同物料号是否跨使用组织共享、创建组织和使用组织字段的真实要求、BD_MATERIAL 的实际字段类型。
- **未确认处理：** 只读查询和假 ERP 可继续；真实 Save 保持禁用。

## 9. 第一条可验收纵向切片

### 9.1 范围

只做以下分支，不扩展全部 231 个节点：

1. **成品：** `finished.01.01` 冷插骨架，系列取单槽/双槽/多槽，材质取 PET/PBT。
2. **半成品：** `semi.01.01` 冷插骨架（未插针），使用同一注塑材质域。
3. **五金成品：** 机壳 + 五金材质 + 表面处理，验证两个并行维度。
4. **五金毛坯：** 机壳/底壳 + 五金材质 + 固定 `00`，验证固定补位不能被客户端覆盖。

### 9.2 纵向流程

```text
草稿规则
  → 发布前静态校验
  → 页面选择主路径和并行维度
  → 预览：显示每个段的来源、规则版本、命名空间、未分配状态
  → 分配：事务取号、写身份键和幂等键
  → 假 ERP Save/View：模拟成功、重复、字段错误、UNKNOWN
  → MES 回读对账：MATCHED / PENDING_EXTERNAL / CONFLICT
```

### 9.3 必须通过的验收用例

| 编号 | 用例 | 预期 |
|---|---|---|
| V1 | 成品冷插骨架/PET/单槽预览 | 显示主路径、材质段、规则版本；不占流水 |
| V2 | 半成品冷插骨架/PET/单槽与 V1 同时分配 | 总类前缀或共享流水策略能阻止完整号码重复 |
| V3 | 注塑分支选择五金材质 | 预览拒绝，错误指向维度域 |
| V4 | 五金毛坯请求中夹带试图修改固定 `00` 的值 | 服务端拒绝客户端覆盖；正常请求由规则自动生成 `00` |
| V5 | 表面处理选择未确认值 | 预览拒绝，不进入正式分配 |
| V6 | 同一幂等键重复分配 | 返回同一分配结果，不消耗第二个流水 |
| V7 | 身份规格由 A 改为 B | 生成新的身份键，要求重新预览 |
| V8 | 规则从 v1 发布为 v2 | 历史编码仍指向 v1；同命名空间流水不回零 |
| V9 | 假 ERP 返回 UNKNOWN/超时 | MES 保留已分配状态，进入对账，不盲目重号 |
| V10 | 跨账套或未授权组织请求 | 后端拒绝；不能由前端下拉框绕过 |

## 10. 现在明确不做的事

- 不把 16 个待确认节点改成正式启用节点。
- 不为变压器候选类别和系列生成笛卡尔积。
- 不把“编码输出成功”当作“ERP 物料已创建”。
- 不用创建组织/使用组织字段掩盖完整物料号碰撞。
- 不用一条自由文本规格拼接字符串代替身份键。
- 不在 K3Cloud MCP 会话丢失时切换成写入模式或直接调用真实 ERP 写接口。
- 不修改既有未提交代码来“顺便重构”；本附录只记录设计和验收边界。

## 11. 推荐的实际执行顺序

### 第一步：先做规则内核的最小演算测试

先固定四个测试规则和上述 V1–V10，用纯内存/假 ERP 验证：段位来源、碰撞、身份、流水和状态机。该步骤不依赖真实 ERP。

### 第二步：把演算模型接入草稿/发布校验

将 `dimensionRefs`、`identityFields`、`fixedSegments`、`sequencePolicy` 和 `allowedCombinations` 纳入规则版本；发布校验必须能报告“哪两条分支会碰撞、哪个值未确认、哪个域不适用”。

### 第三步：只交付一条维护纵向切片

管理页面先支持四个分支的新增/编辑/差异查看/发布/停用，不要一开始为 9 组 231 个节点设计全部特殊表单。字典继续作为共享数据，不复制到每个级联节点下面。

### 第四步：恢复 K3Cloud 只读证据

由宿主实际重启 `k3cloud_readonly` 后，重新取 `BD_MATERIAL` 元数据和小样本；成功前沿用 `PENDING_EXTERNAL`。成功后补字段契约测试，但仍不自动进入真实写入。

### 第五步：业务只需确认 D1–D6

拿真实脱敏编码样例集中确认 D1–D6；确认后只发布对应分支。未确认项保持禁用，不再阻塞已经证据充分的分支。
