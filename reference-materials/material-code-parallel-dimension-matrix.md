## 1. 设计原则

物料由一个主分类路径和多个并行维度共同描述。分类路径表示物料身份；材质、表面处理、系列、形状、规格是可复用的维度。分支规则选择哪些维度参与、按什么顺序形成编码段。BOM、图纸、工艺路线的版本作为物料关联数据保存，不默认进入物料编码。

推荐结构：物料族 → 主分类路径 → 并行维度 → 固定段/补位 → 唯一流水号。发布的规则版本应保存全部段位、组合约束和引用字典快照；历史物料继续指向当时的规则版本。

**九组不是九个独立物料命名空间。** 夹具的九组中，原材料、辅助材料、成品、模具与变压器、半成品、注塑产品配件是六组物料/工装分类来源；注塑材质、五金材质、表面处理是三组共享维度字典。“模具与变压器”又包含两个顶层类别。材质、处理仅在业务明确要求把它们当作独立物料时才另建物料分支及流水规则，不能因为原图有编号表就自动给每个字典值创建 ERP 物料。

| 方案 | 做法 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| 单棵级联树 | 把材质、处理、系列全部塞入父子节点 | 对现有页面改动少 | 字典重复、跨族复用困难，任意组合难以约束 | 不推荐 |
| 并行维度矩阵 | 主分类树 + 共享维度字典 + 分支组合规则 | 贴合原图，能保持编码段来源清楚 | 需要扩展当前规则求值与维护页面 | 推荐 |
| 完全自由的规则脚本 | 管理员编写表达式拼码 | 表面灵活 | 审计、权限、安全和迁移成本高 | 本任务不采用 |

原图左侧还有总类标记：成品 1、半成品 2、原材料 3、辅助材料 4。它们是否正式进入物料编码首段、是 1 位还是补齐 2 位，图片和现有夹具不足以证明。下表沿用各局部规则图能辨识的段位，不把这个总类标记静默加到任何示例编码。

| 维度 | 原图代码范围 | 值域示例 | 可引用的主族 | 维护约束 |
|---|---|---|---|---|

| 系列 | 依各分类 | 单/双/多槽型，外壳/灯/线夹，模具型式 | 对应产品类别 | 系列值的代码只在父产品类别下解释 |

| 规格属性 | 不定长 | 厚度、尺寸、颜色、牌号、包装单位、电气参数等 | 全族 | 默认只进入规格文本和主数据属性；是否占码需另行确认 |

系列、形状在具体分支中可以表现为主分类末级节点，**同一次编码只取一次代码**：若已从路径节点取了“单槽01”，不得再从并行维度重复追加“单槽01”。共享字典要用稳定值 ID 引用，代码和名称允许在新版本中变更；已发布版本保留快照。规格中哪些属性决定“不同物料”应由分支的身份字段清单确定，不能把整段自由文本拼成去重键，也不能把颜色、尺寸等变化一概视为同一物料。

## 5. 编码组装与冲突规则

下表用“竖线”展示逻辑段边界；NNNN仅是流水号占位符，不能据此认定生产位数、起点或分隔符。示例均不得作为ERP可写编码。

|---|---|---|---|---|

| 原材料CP线/圆状 | 02｜04｜01｜NNNN | 形状01 | 02｜04｜01｜NNNN | 是否额外占用材质段仍待确认 |

**数字前缀碰撞是发布阻断项。** 示例中的成品冷插骨架和半成品冷插骨架都可形成 `01｜01｜01｜01｜…`。如果总类标记不入码，两个来源不能各自独立开同前缀流水后再依赖“物料族”字段区分，因为 ERP 最终接收的是完整物料号。发布前必须先确认以下二选一：由业务批准互斥的总类前缀及位数；或在同一 ERP 账套下为碰撞前缀共用一个原子流水号池。两者都没有证据时，碰撞分支不得激活。

建议以“租户 + 目标账套 + 分支身份字段清单的规范化值”判断是否为同一业务物料；身份字段包括主分类叶节点、必需维度值 ID 和该分支指定的身份规格属性，不是任意规格文本。编码分配时服务端读取已发布版本、计算段位和前缀、在唯一约束及事务中分配；完整编码至少在同一目标账套内唯一，创建/使用组织作为授权和 ERP 样本核验条件，不擅自缩小完整编码唯一范围。ERP 是否允许跨组织共享同一物料号，需从目标账套样本验证。规则版本、源维度值 ID、最终编码和 ERP 回读 FID 应一起留痕。

| 校验项 | 失败条件 | 处理 |
|---|---|---|
| 路径 | 子节点不属于选中的父节点，或路径未到合法终点 | 拒绝预览 |
| 维度域 | 注塑分支选了五金材质，或引用未确认的维度值 | 拒绝预览/发布 |
| 必填 | 外加工后壳体缺材质或处理方案 | 拒绝预览 |
| 条件补位 | 分支要求00却被手工换成别的值 | 服务端按规则生成，不接收客户端覆盖 |
| 复合处理 | 用户任意拼“喷粉+电泳”，字典没有该组合值 | 拒绝；只有字典中的原子处理方案可选 |
| 版本 | 修改已发布规则或停用仍被使用的维度值 | 新建草稿版本，保留历史快照 |
| ERP | 同编码在目标账套/组织已存在 | 进入对账/冲突，不盲目重复写入 |
| 跨分支碰撞 | 两条已发布分支可产生相同完整编码，且没有统一前缀或共享流水策略 | 阻止发布；不得以物料族字段掩盖 ERP 号码冲突 |

### 5.1 分支规则的最小可维护结构

不引入自由脚本语言；每个分支用受限声明式配置表达下表字段。表是目标契约，不表示当前数据库和页面已经实现。

| 对象 | 最少字段/语义 | 发布时的检查 |
|---|---|---|
| `ruleVersion` | 族 ID、版本号、状态、来源图/业务确认记录、适用账套、发布时间 | 只能由草稿发布为新版本；不得原地改已发布版本 |
| `classificationNode` | 稳定节点 ID、父 ID、本级码、名称、确认状态、可选叶子标记 | 同父代码不重复；引用路径完整；未确认节点不可激活 |
| `dimensionValue` | 维度域、稳定值 ID、两位码、名称、状态、来源 | 同域代码唯一；跨域相同代码必须带域解释 |
| `branchRule` | 叶节点 ID、适用条件、身份字段清单、必需/可选/禁止维度、值域限制 | 每个可发布叶节点命中唯一分支；不能出现互斥条件同时成立 |
| `segments` | 有序段列表，每段为路径节点、维度引用或固定 `00` 三选一，附长度 | 每个代码只出现一次；段数、顺序与已确认样例一致 |
| `sequencePolicy` | 流水作用域、位数、起点、步长、耗尽/断号策略 | 所有可碰撞前缀共享同一原子分配池；未定义不得发布 |
| `allocationTrace` | 账套、规则版本、规范化身份键、完整编码、组织、幂等键、ERP FID/状态 | 分配和回读可追踪，重试不产生第二号码 |

规则发布前用全量可用路径与允许维度值做前缀冲突检查；不必预枚举每一种尺寸和自由文本规格。冲突检查还需覆盖已有已发布版本与目标账套中已存在的物料号。管理页只负责草稿编辑、差异审阅和发布申请；后端承担最终校验、权限和审计。
