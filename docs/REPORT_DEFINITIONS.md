# 报表定义：保存固定日报模板与筛选条件

报表定义列表、创建和编辑已经接入服务端 SQLite 持久化，不使用浏览器本地存储充当保存。定义按已验证的 tenant / organization / account 三层范围独立保存，同一账套内共享；刷新页面或重启服务后仍可读取。

## 本期可以做什么

在「报表定义」新增固定的销售日报或采购日报模板，保存名称、开始日期、结束日期及可选客商名称。客商名称是精确匹配，日期包含起止两端，日期留空表示该端不限。模板只读取当前账套已保存且未软删除的日报，不执行自定义 SQL、公式，不查询 ERP，也不触发外部发送。

列表可查看定义和当前版本，预览显示筛选后的日报明细、记录数、数量合计及人民币金额合计。金额沿用日报行内已保存的人民币金额与历史汇率，不重新折算；数量可能含不同计量单位，不作为统一计量。演示数据会明确标记，不当作真实业务数据。预览反映当前数据，不是不可变历史归档。

页面参考 dailyReport 的「日期/客商筛选 → 指标卡 → 明细」模式。dailyReport 原项目没有可复用的用户定义模型，本期是在明确的最小范围内新增定义存储，而不是将其收件组或发送计划改名为定义。

## 谁可以维护和查看

- 只有当前账套角色为 `admin` 的成员可以创建或编辑。`plm_manager`、`reviewer`、`member` 不能写入定义。
- 查看列表、详情和预览仍受现有日报业务线权限约束；只有销售权限的成员看不到采购定义或采购预览。无权限、其他账套或不存在的定义 ID 返回 404。
- 兼容既有日报权限：主档未配置的账套仍遵循现有宽松读取规则；配置主档后，普通成员业务线权限取决于有效客商归属。本功能不扩大该规则。
- 请求范围来自已验证会话，而不是请求体中的 tenant/org/account。伪造范围头不能越权。

## 编辑与历史

每次创建或编辑都保存操作者、时间和递增版本，并在同一 SQLite 原子写入中保留定义修订审计副本。编辑必须携带 `expectedVersion`，旧版本返回 409，避免覆盖他人的修改；同一账套同名定义也返回 409。

编辑页面将定义 ID 放入 URL 的 `definitionId` 参数，刷新后从服务端重新加载。保存成功后再次 GET 确认，并刷新服务端列表。编辑只影响今后对此定义的预览，不改动既有日报、归档快照或发送计划。

## 接口

所有接口挂在现有认证、三层范围授权和同源保护之后，并返回 `Cache-Control: private, no-store`。

| 方法与路径 | 说明 |
|---|---|
| `GET /api/report-definitions` | 返回当前成员有权查看的 `{ definitions: [...] }`。 |
| `POST /api/report-definitions` | 管理员创建定义，返回 201。 |
| `GET /api/report-definitions/:id` | 读取有权查看的定义。 |
| `PATCH /api/report-definitions/:id` | 管理员编辑，要求当前 `expectedVersion`；返回新版定义。 |
| `GET /api/report-definitions/:id/preview` | 根据已保存定义生成只读预览。 |

创建示例：

```json
{
  "name": "十月销售日报",
  "template": "daily-sales",
  "filters": { "from": "2026-10-01", "to": "2026-10-31", "partyName": "示例客户" }
}
```

`template` 只能为 `daily-sales` 或 `daily-purchase`。编辑提交同样字段，另加 `expectedVersion: 1`。名称最长 120 字、客商名称最长 200 字；不合法日期、反向区间、未支持字段、公式及跨账套配置都拒绝保存。

## 本期明确不包含

不提供自定义指标、公式、维度或布局设计器；不提供删除、发布审批、回滚或个人私有定义；不将现有发送计划绑定到新定义；不扩展原系统的收件人或发送渠道。现有报告展示和发送计划仍使用其原有固定报告，不会因为创建或编辑定义而发生变化。

```bash

npm test --prefix server
```

服务端测试使用临时 SQLite 和独立测试进程，不访问真实业务数据库或外部 ERP/邮件/钉钉服务。浏览器验证同样在独立临时数据库和测试管理员下执行，不部署、不推送代码。
