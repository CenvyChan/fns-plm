# 物料建档闭环

物料工作台新增「K3 来源 → PLM 草稿 → 编码预览」入口。搜索来源编码、名称或规格，选择相似项复制，再修改名称、规格、单位。来源编码、ERP 内码、审核状态和组织上下文不作为新物料身份继承。预览和分配均由服务端计算，客户端不能提交自己生成的号码。

**分配结果是当前 PLM 账套的持久化编码保留，不是 ERP 已建料。** 本实现没有 Save / Submit / Audit / Allocate ERP 写接口。ERP 外部操作者可能独立创建同号，正式写入阶段仍须重新核验；不能把本地唯一约束宣称为 ERP 全局锁。完整扫描也不是 K3 数据库事务快照。

## 规则与明确阻断项

总类为 `1.` 产成品、`2.` 半成品、`3.` 原材料，保留点号，不沿用旧的通用五位流水。只在已确认规则和本地目录能唯一确定完整前缀及其各段映射时才允许分配。

| 类型 | 已知口径 | 当前服务端行为 |
| --- | --- | --- |
| 产成品 | 通常三位流水 | 当前类别和完整固定段映射未唯一核实，预览标待确认，分配拒绝 |
| 模具 | 例外为模具类别.系列 + 五位流水 | 类别、系列具体目录绑定未确认，阻断，不猜测笛卡尔组合 |
| 半成品注塑 | 无注塑毛坯；示例 `2.01.02.0317###` | `03/17` 等各段映射存在歧义，阻断；不得作为不透明完整前缀直接放行 |
| 半成品五金毛坯 | 示例 `2.02.03.05#####` | 类别和各段尚未形成唯一可信目录绑定，阻断，不外推其他分类 |
| 半成品五金表面处理 | 示例 `2.03.02.0117###` | `01/17` 等映射未唯一确认，阻断 |
| 原材料 | K3Cloud `3.` 开头完整分组 + 点号 + 最后五位流水 | 可执行：完整分组由来源唯一确定，源物料编码须精确符合分组 + 点号 + 五位流水；不猜测额外参数段 |

没有提供管理员自由填写前缀/依据就绕过目录验证的接口。不能把历史文档、旧五位通用规则或客户端分类树当作用户的新批准依据。

找不到同池现有号时，首号/起点未确认，阻断；同前缀有不同流水位数的旧号时，阻断。取当前完整快照、工作区和历史保留号的最大值加一，不填补断号，不自动扩位。五位 `99999` 耗尽阻断。算法单测中的三位流水 fixture 只验证通用边界，不能据此放行当前被阻断的业务类别。任何阻断均不写保留表、不消耗流水。

## 后端与权限

所有接口位于 `/api/material-closure`，复用服务端会话验证及 `X-Tenant-ID` / `X-Organization-ID` / `X-Account-ID` 的完整三层范围。查询、复制、编辑、预览、分配及审计仅 `admin` / `plm_manager` 可用。请求体自带 scope 不影响授权。其他账套的来源和草稿 ID 不可引用。

| 方法 / 路径 | 行为 |
| --- | --- |
| `GET /source?q=...` | 读取当前账套持久化完整物料快照，返回最多 200 个筛选项，不访问 ERP |
| `POST /source/refresh` | 复用现有 LoginByAppSecret / ExecuteBillQuery 只读连接器完整分页读取；显式绕过查询缓存 |
| `POST /drafts {sourceId}` | 服务端复制允许字段，生成新草稿 ID 与 DRAFT 号，原始来源写入不可变审计 |
| `PATCH /drafts/:id {name,specification,unit}` | 仅编辑上述差异字段并审计；已保留号码禁止修改身份 |
| `POST /drafts/:id/preview {kind,prefix}` | 返回候选号或 `blocked:true` 及待确认原因，不写保留表；系统异常不伪装为业务阻断 |
| `POST /drafts/:id/allocate {kind,prefix}` | 事务重新计算最大号并保留；同一草稿同规则重试幂等，不同规则拒绝 |
| `GET /drafts/:id/audit` | 回读复制、修改和分配的操作者、来源与快照、规则版本、前最大号 |

分配用 SQLite `BEGIN IMMEDIATE`，保留表对 `(tenant,organization,account,code)` 和同范围 `material_id` 分别设唯一约束；保留号、工作区物料和分配审计在同一事务提交或回滚，支持共用同一 SQLite 文件的多进程。保留号永不回收。审计表有禁止 UPDATE / DELETE 的触发器。旧 `/materials` CRUD 不允许伪造来源、提交 `1./2./3.` 正式形态号码或覆盖来源草稿，避免绕过审计/分配。

分配要求最近五分钟以内的完整物料快照，连接器版本未变化，来源物料仍存在，且复制审计中的来源指纹、来源代际、`groupId` 和 `groupNumber` 均与当前快照一致；草稿来源 ID、两个分组字段也必须与复制审计一致。完整扫描最高 10,000 行；超限、重复 ID/编码、缺关键字段、越外部组织、分页失败都不替换旧快照。快照提交带版本比较，避免并发扫描静默覆盖。

完整快照及刷新、复制、分配审计保存版本化 SHA-256 来源指纹。指纹仅由非秘密字段计算：规范化 HTTP(S) 端点命名空间（协议、主机、端口、服务路径）、外部账套 `accountId`、外部 `organization`、FormId 和八字段映射。只持久化哈希，不把原始端点/连接配置或凭据写入物料快照/审计；用户名、应用标识、密码、密钥、令牌和会话均不参与该指纹。字段对象键顺序、等价端点尾斜杠和凭据轮换不改变身份，但保存设置后仍须重新刷新以满足连接器版本校验。

刷新成功且来源身份变化后，旧未授号草稿必须重新查询并复制，即使内码和两个分组字段完全相同。来源代际由服务端在保存连接器时维护，非秘密身份变化即更新；即使中途没有成功刷新，切回原来源后再刷新也不会复活旧草稿。凭据轮换不改变来源代际。历史快照/复制审计缺少指纹或代际时不作猜测、不自动补证；必须刷新并重新复制。连接器版本变化后禁止从旧快照复制。已授号的同规则重试仅回读原保留回执，不产生新授号，既有保留号不回收。

## 连接器配置与验证边界

在当前账套加密 K3 配置中保存 `materialSource: {formId, fields}`。`fields` 必须显式映射八个不同字段：`id`、`number`、`name`、`specification`、`unit`、`groupNumber`、`groupId`、`organization`。FormId 和每个字段必须已在当前账套 `formAllowlist` 中；不自带通用企业字段名。外部组织来自此连接器的 `organization`，强制按该字段过滤并核验返回组织，内部三层范围另行隔离。保存设置不自动读取 K3。

本次开发与测试只使用临时 SQLite、固定 fixture 与 loopback K3 HTTP 替身；未读取真实 K3 凭据、未访问真实 K3，也未写回 ERP。dailyReport 本地源码核查显示其物料搜索属于库存交易明细筛选，并无可移植的相似物料复制、编码预览或原子流水机制；这里只参考显式筛选与确认的交互，不将日报代码或历史文档当作编码规则批准证据。

来源隔离回归涵盖外部账套、组织、端点服务路径、FormId、字段映射变化时相同内码/分组碰撞，`groupId` 单独变化、`groupNumber` 变化、切回原来源（含无中间刷新）、双进程并发保存连接器、凭据轮换、历史缺指纹、阻断不占号，以及重启后指纹/审计回读。连接器保存本身使用即时事务，使旧身份读取、代际更新、修订递增及配置写入不可被并发保存拆开。纯函数单测逐一验证全部八字段和端点协议/主机/端口/路径的身份区分，并用抛错访问器证明指纹函数不读取凭据字段。验证在仅启用 loopback 的独立网络命名空间中执行，使用空白环境和 `/dev/null` dotenv 配置，不能访问真实外部服务；保留原双进程并发、审计失败事务回滚及重启持久化测试。
